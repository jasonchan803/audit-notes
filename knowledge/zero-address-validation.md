## 零地址验证：什么时候需要，什么时候可以省略

### 为什么需要零地址验证？
- 防止将关键状态变量（如 owner、admin、依赖合约地址）误设为 `address(0)`，导致功能永久失效。
- 防止用户向零地址转账或授权，导致资产永久丢失。
- 作为防御性编程的一部分，降低人为错误风险。

### 什么时候“必须”验证？
| 场景 | 原因 |
| :--- | :--- |
| 用户输入的 `to` 地址（转账、铸造、赎回） | 防止用户错误操作导致资产丢失 |
| 管理员设置的关键地址（owner、依赖合约、代理地址） | 防止因误配置导致合约功能永久失效 |
| 初始化函数中的关键参数 | 初始化通常只能执行一次，错误无法回滚 |

### 什么时候“可以省略”？
| 场景 | 权衡 |
| :--- | :--- |
| 内部调用中已验证的来源 | 上游已检查，无需重复 |
| 极低频调用的管理函数 | 如果修复成本低且错误可重新部署，Gas 成本可能不值得 |
| 项目方依赖治理/多签流程 | 若治理流程已经提供了足够的防护（如多签、提案审查），代码可适当简化 |

### 审计师的判断原则
- **默认建议：添加零地址验证**，因为修复成本极低，且可以防止人为错误。
- **如果项目方拒绝**：评估该地址被设为零后是否可恢复（如可通过治理重新设置），以及错误发生的概率。如果错误成本低且修复方便，可接受不添加。

### 案例
- **PoolTogether (L-02)**：`to` 地址缺少零地址验证，导致用户资金可能被锁定 → 建议添加。
- **Yield Protocol (L-18)**：项目方认为部分场景不值得增加 Gas 成本 → 审计师判断为 Low，不作强制要求。
